# UI 设计规范

本规范是万能工具箱的默认 UI 约定。新增模块和修改现有界面均须遵循，变更公共规则时同步修改本文件与实现。

## 参考与定位

参考 [Codex 桌面应用](https://openai.com/index/introducing-the-codex-app/) 的桌面工作区方向：弱化装饰、强调内容、稳定侧栏、清晰层级、按需展开详情。

以下颜色、尺寸和 CSS 类是**本项目的设计决策**，不是提取的 Codex 官方设计变量，也不要求像素级复制。沿用工具箱自己的名称与功能，不复制品牌标识、对话输入框或与工具无关的布局。

## 视觉原则

- 中性色为主体：浅色侧栏 + 内容底色，深色模式使用对应语义变量。通过留白、字重、细边框组织信息。
- 导航选中使用中性底色和字重；普通按钮为描边，主要操作使用高对比黑白填充。
- 红色只表示危险操作和错误，绿色只表示成功；状态同时提供文字，不仅靠颜色。
- 不引入装饰渐变、玻璃效果、大阴影、大面积品牌色、巨型标题或重复卡片包裹。
- 主体内容优先。帮助说明、完整命令、路径等详情按需展开，关键辨识信息（如工作目录）保留在列表。

## 唯一视觉来源

| 文件 | 职责 |
| --- | --- |
| `src/styles/tokens.css` | 颜色、字体、字号、间距、圆角、控件高度、侧栏宽度；含系统深色模式 |
| `src/styles/ui.css` | 原生控件和公共布局样式，统一使用 `ui-` 前缀 |
| `src/App.css` | 全局排版、Shell、导航、焦点与响应式布局 |
| `src/modules/<module>/*.css` | 模块专属的数据布局和尺寸，不定义另一套主题或基础控件 |

模块不得硬编码主题颜色、覆盖全局 `--ui-*` 变量或添加未限定范围的元素选择器。图像、图表、游戏中有业务意义的颜色可以局部定义，但工具栏、设置与反馈仍遵循公共 UI。固定数据列宽等布局尺寸可由模块决定。

## 尺寸与排版

| 项目 | 默认值 |
| --- | --- |
| 正文 | 14px / 1.5，系统字体，中文跟随系统字体回退 |
| 控件、表格、导航 | 13–14px |
| 辅助文字 | 12px，不能把主要内容降到此字号 |
| 页面标题 | 22px / 1.4，600 字重，每页一个 h1 |
| 区块标题 | 16px，600 字重 |
| 等宽内容 | `--ui-mono`，用于命令、端口、协议与技术值 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px，使用对应 `--ui-space-*` |
| 圆角 | 控件 6px，表格容器与反馈区域 8px |
| 常规控件高度 | 最少 36px，文本不能截断 |
| 侧栏 | 220px；窗口宽度 ≤600px 时 140px，保留文字导航 |
| 内容边距 | 32px；窄窗口纵向 24px、横向 16px |

颜色按语义选择：正文 `--ui-text`，辅助文字 `--ui-muted`，内容 `--ui-bg`，次级区域 `--ui-surface`，边框 `--ui-border`，表单边框 `--ui-control-border`，焦点 `--ui-focus`。控件描边默认弱化，输入与描边按钮在 hover / focus 时加深为 `--ui-muted`，焦点另有 `--ui-focus` 描边。不要通过降低父容器透明度来表现正常的次级文字。

## 页面与交互

页面按“标题与简短说明 → 输入/操作 → 状态反馈 → 结果”的顺序组织。Shell 与主内容独立滚动；模块不嵌入自己的全局侧栏或主题。

- 工具栏使用 `.ui-toolbar`；字段使用 `.ui-field` + 原生 `label`，不要只用 placeholder 充当标签。
- 输入使用 `.ui-input`，按钮使用 `.ui-button`。每个操作区域最多突出一个主要按钮，追加 `.ui-button--primary`。
- 危险操作先展示对象、路径和影响范围；确认按钮追加 `.ui-button--danger`，取消使用普通按钮。异步执行中禁用重复操作。
- 信息、错误、成功用 `.ui-feedback`，追加 `--error` 或 `--success` 修饰类；错误使用 `role="alert"`，结果使用 `role="status"`。失败后保留恢复方式，不能只改颜色或静默失败。
- 长表格使用 `.ui-table-wrap` + `.ui-table`；内容超宽时容器横向滚动，页面不能整体横向溢出。可滚动区域提供键盘焦点与名称。
- 详情和说明优先使用原生 `details/summary`。展开后内容可选中复制；完整路径与命令换行显示，不仅靠鼠标悬浮才能读取。
- 链接、按钮、输入、summary 保留可见焦点。仅图标按钮必须有可访问名称；图标的选择与用法见「图标」一节。
- 显式区分未查询、加载中、无结果、无权限、不支持和失败。不要让浏览器预览伪装成可操作的原生环境。
- 默认无动画；如将来需要动效，限制为短暂状态反馈，并支持 `prefers-reduced-motion`。

## 最小接入示例

```tsx
<section>
  <h1>工具名称</h1>
  <p>一句话说明用途。</p>
  <form className="ui-toolbar" onSubmit={handleSubmit}>
    <div className="ui-field">
      <label htmlFor="tool-input">输入内容</label>
      <input className="ui-input" id="tool-input" />
    </div>
    <button className="ui-button ui-button--primary" type="submit">执行</button>
  </form>
</section>
```

CSS 通过 `App.css` 全局引入，模块无需重复导入。当前使用原生元素与 CSS，不增加 UI 组件库、Theme Provider、CSS-in-JS、通用 Form/Table 框架或仅包装样式的 React 组件。出现多个模块重复的交互逻辑时，再提取小型共享组件。

## 图标

界面图标统一使用 Lucide 线性图标（`lucide-react`），不混用其他图标库；emoji 不充当功能图标。

- 默认 16px、描边约 1.5–2px，颜色继承 `currentColor`，不单独着色；语义着色仍受红色 / 绿色限制。
- 图标不单独承担含义：导航与列表保留文字标签，配文字的图标标记 `aria-hidden`；仅图标按钮提供可访问名称。

## 主题

- 主题选项为浅色 / 深色 / 跟随系统（默认），在「设置」页修改（Shell 页面 `#/settings`，经侧栏底部链接进入）；选择经 `localStorage` 持久化，`index.html` 的内联脚本在渲染前应用以避免闪烁。
- `<html>` 上的 `data-theme="light|dark"` 覆盖系统结果；`tokens.css` 的深色变量同时由媒体查询和 `data-theme="dark"` 提供，两处保持一致。
- 模块只使用语义变量，不读取或判断当前主题，不自行响应 `data-theme`。

## 交付检查

1. 使用现有 token 和公共类；没有新增一套配色、按钮或页面间距。
2. 检查默认桌面尺寸 800×600、宽窗口和窄窗口；路径、命令和表格不会挤出页面。
3. 检查浅色与深色变量，正文对比度目标 ≥4.5:1；焦点、输入边界和状态文字清晰。
4. 键盘可达主要操作，检查禁用、错误、空结果、详情与危险确认状态。
5. 运行前端构建与相关检查；视觉修改应查看实际渲染，不以类型检查代替布局检查。

当前范例：App Shell 和端口管理模块。新增普通工具应复用这些规则；确需偏离时，在模块说明中记录具体原因，若具有通用价值则先更新本规范与公共样式。

可视化样板：[ui-preview.html](ui-preview.html)。运行 `pnpm dev` 后访问 `/docs/ui-preview.html`，或直接用浏览器打开该文件。它引用生产 CSS，使用虚构数据展示基本控件、详情、长路径、反馈及危险确认，不会查询或停止进程，也不注册为业务模块。
